## 🔍 기록 담당이 설명한 것
- 시뮬레이터에서 EDR 이벤트 3,161건을 만들고 `edr-events-*`에 적재했다. 저장 건수도 3,161건이며 검색 대상 샤드 실패는 0건이었다.
- 주요 매핑은 `event_id`, `host`가 `keyword`, `process.pid`와 `process.ppid`가 `long`, `ts`가 `date`, `process.cmdline`이 `text`와 `keyword`다. 정확한 값 검색과 본문 검색을 구분하고, `dynamic: strict`로 예상 밖 필드가 자동 추가되지 않게 했다.
- 사례는 `WS-006`의 `evt-00003006`이다. `rundll32.exe`(PID 46643, PPID 20558)가 `comsvcs.dll, MiniDump` 명령으로 덤프 파일을 만들었고, `evt-00003007`에서 `C:\Windows\Temp\d.dmp` 생성 기록을 확인했다. 이벤트 ID로 근거를 연결해 제시할 수 있다.
- 같은 호스트에서 PID 20558이 재사용되어, 최신 프로세스를 고르면 조사 시각보다 뒤인 `svchost.exe`가 부모로 잘못 연결됐다. 자식 생성 시각 이전 기록을 부모 후보로 찾도록 시간 조건을 추가해 `cmd.exe`를 반환하도록 수정했다고 보고했다. 자동 테스트 8개 통과 및 기존 데이터 3,161건 보존도 확인했다.
- 조사 도구는 최종적으로 악성 여부를 판정하는 대신 프로세스 관계와 활동 기록을 모아 근거를 제공한다. 세 도구 모두 결과의 `event_id`를 유지하고 명령줄은 최대 120자로 요약한다고 설명했다.

2. `evt-00003006`의 프로세스 실행과 `evt-00003007`의 파일 생성을 `event_id`로 각각 다시 조회해 연결할 수 있나요?
3. 명령줄을 120자로 자르면 조사에 필요한 인자나 경로가 잘릴 수 있는데, 요약 결과에서 잘림 여부를 알 수 있나요?

## 📘 문서 담당이 설명한 것
- 검색 파이프라인은 PDF를 파싱하고, 문서 구조를 기준으로 청크를 만든 뒤 출처 정보를 붙여 인덱싱하고 검색한다. `search_playbook(query, k)`는 관련 플레이북·정책 조각을 반환한다.
- `fast`를 텍스트 중심 문서의 기준선으로 두고 9종 PDF를 확인했다. 03에서는 Header 4개와 Footer 2개가 감지됐다. 06은 텍스트 요소가 추출되지 않아 OCR이 필요했다. 01·09는 `fast`에서 Table 요소가 없었지만 `hi_res`로 각각 2개·5개의 표 요소가 나왔다. 06의 `ocr_only` 결과는 텍스트 추출에 성공했지만 한국어 오인식과 글자 간격 오류가 남았다.
- 청킹 실험에서 `max_characters=600`, `new_after_n_chars=600`일 때 21개 청크가 만들어졌다. 21문항 평가에서 키워드 및 hybrid 검색 Recall@3는 0.905, 벡터 검색은 0.810이었다. k14는 모든 방식에서 실패해 한국어 질문과 영어 문서 간 검색이 남은 약점이다.
- 🔍 기록 담당 질문에 대한 답:
  1. `get_process_tree(host, pid)`는 같은 호스트에서 대상 프로세스의 생성 기록을 찾고 `ppid`를 따라 부모를 탐색한다. PID는 호스트 간에 중복될 수 있으므로 모든 조회에 `host`를 포함한다. 같은 호스트에서도 PID가 재사용될 수 있어, 실제 부모를 찾을 때는 자식 프로세스 생성 시각 이전의 부모 기록을 고르는 시간 조건이 필요하다. 부모는 최대 5단계까지 거슬러 올라가도록 설계돼 있다.
  2. `get_process_activity(host, pid)`는 같은 호스트·PID의 네트워크, 파일, 레지스트리, 스크립트 활동을 시간순으로 최대 50건 조회한다. 도구는 활동 증거를 제공할 뿐 악성 여부를 직접 판정하지 않는다. 에이전트가 프로세스 관계와 다른 근거를 함께 검토해 판단한다.
  3. `get_host_timeline(host, around_ts, minutes)`는 기준 시각 앞뒤 기본 10분의 이벤트를 시간순으로 최대 100건 조회한다. 더 많은 결과가 있어 잘렸다면 `truncated: true`로 알린다.
- 티치백에서는 청크 한 건을 열어 본문과 출처를 함께 보여 준다. 실제 반환 결과의 파일·페이지·요소 정보는 인덱싱 결과 확인 후 보완한다.

**🔍 기록 담당의 질문**
1. `get_process_tree()`는 부모 프로세스를 어떻게 찾고, PID가 중복되면 어떻게 처리하나요?
2. `get_process_activity()`는 어떤 활동을 조회하며, 악성 행위인지는 어떻게 판단하나요?
3. `get_host_timeline()`은 이벤트를 몇 건까지 조회하며, 결과가 잘리면 어떻게 알 수 있나요?
